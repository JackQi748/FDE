# 04 · 向非工程师讲清取舍

一句话直觉：非工程师不需要 Transformer 细节，需要**用他们的单位**听懂：风险、钱、时间、控制权——取舍是选项对比，不是术语展览。

## 直觉讲解

**讲清取舍** = 把技术决策翻译成业务后果：选 A 得什么、付什么、放弃什么。结构推荐：

1. 背景目标（他们的词）  
2. 2–3 个真实选项（含「现在不做」）  
3. 每个选项的收益 / 成本 / 风险 / 可逆性  
4. 你的建议与需要他们拍板的点  

避免：堆栈图、缩写轰炸、假精确（「准确率大概很高」）。

```mermaid
flowchart LR
  Tech[技术选项] --> Biz[业务后果]
  Biz --> Trade[显式交换]
  Trade --> Decision[可拍板问题]
```

单位换算示例：

| 技术说法 | 业务说法 |
|----------|----------|
| 提高召回 | 更少漏掉相关政策，但可能多噪音 |
| 人在回路 | 错答不直接到客户，人工多 30 秒 |
| 气隙部署 | 数据不出园，模型迭代慢一个版本火车 |
| Prompt 缓存 | 同样前缀更便宜更快；改模板要谨慎 |

## 工作示例（数字/场景）

**场景 A：开源自建 vs API**

对 CFO/风险：

- API：按量付费，前沿能力快；数据出边界要合同与法务。  
- 自建：控制强，但要人、GPU、值班；总拥有成本常高于「看起来的 token 价」。  
建议：监管数据走 VPC/自建，一般写作走 API——**混合**，并给三年成本带状图而非单点。

**场景 B：延迟投诉**

不要先讲 KV cache。先讲：

- 现在 P95=8s，用户感知「卡」  
- 选项：缩短答案 / 流式先出首字 / 缩小检索 / 换更快模型  
- 各选项对「完整性、费用、工程周数」的影响  
再按需下钻技术。

**场景 C：面试客户模拟**

「成本多少」→ 用他们的风险单位：「一次错答的责任 vs 多雇一个审核」——见客户模拟操练中的评分标准。

## 面试常问取舍

1. **简化是否等于撒谎？**  
   - 简化是分层；底下列假设。被追问能下钻才是诚信。  

2. **多个干系人语言不同**  
   - 同一张取舍表，封面不同：安全看驻留，业务看采用，财务看单位经济。  

3. **被逼选「最好」**  
   - 回应：在约束 X 下最优是 Y；若约束变，结论变。  

4. **对方不懂还点头**  
   - 让对方用自己的话复述决策；复述不出就还没讲清。

## FDE 现场怎么用

- **会前**：一张一页纸选项表，不带长 PPT。  
- **会中**：先决策问题，后技术附录。  
- **会后**：纪要只记「选了什么、放弃什么、谁负责」。  
- **禁忌**：用自信语气掩盖不确定性；把不确定性写成区间与验证计划。

### 比喻使用规则

- 好比喻：映射一种关系（错误预算≈配额）。  
- 坏比喻：娱乐化严肃风险（「AI 像魔法」）。  
- 比喻之后立刻回到数字与责任人。

### 30 秒结构（面试）

「目标是…；选项有…；我建议…因为风险/成本…；需要您拍板的是…。」

## 课堂小结

取舍沟通是 FDE 的产品表面。下一篇把「谁能决定部署形态」说清楚——决策权比架构图更能决定时间线。

## 三种听众的同一决策

**部署要不要气隙**（同一事实，三种封面）：

- 给安全：攻击面、驻留、审计出口  
- 给业务：迭代速度、功能滞后、试点能否本季度见效  
- 给财务：硬件/人力 TCO vs 云 API 三年带状成本  

禁止三场会讲三套互相矛盾的「最优」；矛盾处必须抬到决策权表上的 D。

### 检查你是否讲清了

- 对方能复述选项与放弃项吗？
- 决策问题是否单句可念？
- 数字是否带来源日期？
