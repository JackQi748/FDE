# AI 事件响应

一句话直觉：AI 事故不只是 500——还包括提示注入得手、串租、有毒输出、模型投毒与密钥进提示；响应要有人、有剧本、有开关。

## 直觉讲解

**事件响应（Incident Response, IR）**：准备 → 识别 → 遏制 → 根除 → 恢复 → 复盘。AI 系统把经典 IR 扩到「内容与决策」层。

典型 AI 事件类别：

| 类别 | 例 |
|------|-----|
| 安全 | 注入导致工具滥用、数据外泄 |
| 隐私 | PII 进日志/被模型回显 |
| 完整性 | 污染语料、错误索引全量发布 |
| 可用性 | 供应商中断、成本打爆 |
| 安全对齐 | 有害/歧视输出大面积出现 |
| 合规 | 未经批准用途被启用 |

```mermaid
flowchart LR
  Det[检测] --> Tri[分级]
  Tri --> Con[遏制:关工具/切只读/下线]
  Con --> Ev[取证:审计与版本]
  Ev --> Fix[修复]
  Fix --> PIR[复盘与门禁]
```

关键准备物：**击杀开关**（禁用工具、切规则引擎、降级FAQ）、**通讯模板**、**取证包字段**、**值班 RACI**。

## 工作示例（数字/场景）

**场景 A：间接注入触发批量外发**

检测：出站 webhook 突增。遏制：吊销工具凭证、断出网、会话失效。取证：相关 `request_id`、检索 `doc_id`、提示模板版本。根除：清毒文档、修过滤器、加 HITL。复盘：红队样本入库。

**场景 B：幻觉政策致客诉**

非安全类但需 IR 轻量流程：回滚索引版本、公告更正、抽检相似问答。

**场景 C：半夜模型供应商错误内容**

降级到备用模型或只读检索摘要；错误预算会议次日开。

| 严重级 | 例 | 初始动作 |
|--------|-----|----------|
| SEV1 | 大规模泄密/资金损失 | 全停高危工具+管理层 |
| SEV2 | 局部串租/有害输出 | 租户级禁用+修复 |
| SEV3 | 单点幻觉投诉 | 工单+内容修复 |

## 面试常问取舍

1. **是否一出事就关停整个助手？**  
   - 看爆炸半径；优先关高危能力，保留只读价值。  

2. **与传统 AppSec IR 合并？**  
   - 应合并值班，但剧本要有 AI 特有条目。  

3. **要不要公开披露？**  
   - 依法务/合同；技术侧准备事实时间线。  

4. **复盘罚谁？**  
   - 罚系统缺口；对人不对背锅文化。  

## FDE 现场怎么用

1. 上线前交付最小 IR 手册（含击杀开关操作）。  
2. 演练一次注入或串租桌面推演。  
3. 保证审计字段够取证（见审计篇）。  
4. 与客户 SOC 对接升级路径。  
5. 口条：「没有开关的智能，是不可遏制的风险。」

## 深入：通讯、取证与复盘

### 通讯
内部频道、客户成功、法务、公关分角色；技术事实与对外表述分离审批。

### 取证包最小清单
时间线、request_id 列表、模型/提示/索引版本、工具调用、相关文档 id、变更单。

### 24/72 小时
24h：遏制与客户通知（若需）；72h：根因与临时控制；两周：门禁修复验证。

### 桌面推演题目
「检索库被植入注入句并触发外发」——走完角色与开关。

### 课堂小结
IR 能力=开关+审计+剧本+演练；缺一则只有事后争论。

## 速查清单与一周落地

### 进场 60 秒自检
-  成功 标准是否可测、可告警？
- 失败时能否阻断下游或降级，而不是静默？
- 关键对象是否有明确 owner 与版本？
- 是否存在可演示的回滚/重跑路径？
- 安全与隐私控制是否与功能同迭代，而非上线贴纸？

### 建议一周节奏
| 日 | 动作 |
|----|------|
| D1 | 画现状与爆炸半径；点名权威源/身份/边界 |
| D2 | 定最小验收数字与反例（应失败用例） |
| D3 | 落地最小控制或管道切片 |
| D4 | 用真实量级/红队样本验证 |
| D5 | 写 Runbook、客户沟通点与遗留风险 |

### 面试 60 秒版本
先讲问题的业务爆炸半径，再讲 2–3 个关键控制与可观测证据，最后给回滚/门禁。FDE 分数来自可运营，而不是名词堆叠。

### 常见反模式（再强调）
- 只有快乐路径 Demo，没有否定测试  
- 重试/自动化放大事故（缺幂等或缺开关）  
- 把提示词/文档当唯一强制执行点  
- 指标不可计算或无人看  
- 成本、质量、安全拆成三张互相矛盾的嘴
