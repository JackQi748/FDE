# 18 · 权限感知 RAG（Permission-Aware RAG）

## 一句话直觉

**先裁可见世界，再检索**——权限是检索系统的一部分，不是提示词里的礼貌请求。

---

## 直觉讲解

企业知识库从来不是全员明文。RAG 若忽略 ACL，就变成「聪明的泄密引擎」。权限感知 RAG 要求：用户身份 → 可见文档集合 → 只在该集合上检索/重排/生成；审计能回答「为何这条证据出现在此次回答」。

常见执行点：

| 执行点 | 做法 | 强度 |
|--------|------|------|
| 预过滤 | 索引元数据 `acl_tags` / 行级安全 | 强（推荐）  
| 分区/多库 | 按租户物理隔离 | 强 |
| 后过滤 | 先搜后删无权限 | 弱（易空/易漏） |
| 提示约束 | 「不要引用无权限内容」 | **极弱，禁止当唯一控制** |

```mermaid
flowchart LR
  U[用户身份] --> P[策略引擎]
  P --> V[可见集合]
  V --> R[检索]
  R --> G[生成]
  G --> A[审计：证据与策略版本]
```

还要注意「间接泄漏」：即使文档本体不可见，摘要记忆、同事粘贴、日志里的片段也可能泄。生成侧要对输出做敏感分档；工具侧禁止用服务账号读全世界再让模型「自己判断能不能说」。

## 工作示例

**场景**：集团知识库，子公司 A/B 隔离，另有「仅 HR」空间。

| 用户 | 查询 | 期望 |
|------|------|------|
| A 员工 | 差旅标准 | 只命中 A 政策 |
| A 员工 | B 的薪资带宽 | 空结果或拒答，无片段进上下文 |
| HR | 某薪资制度 | 可检索 HR 空间 |
| 管理员 | 任意 | 仍走审计，非静默全能 |

**测试用例必须自动化**：渗透式提问 + 检查响应与**检索日志**是否出现禁止 `doc_id`。只看最终自然语言不够——模型可能「不知道」但日志已拉取。

**文档级 vs 段落级 ACL**：同一文件部分章节机密时，要在块级打标，或拆分文档。

## 面试常问取舍

**Q：向量库过滤不够细怎么办？**  
A：同步到支持行级安全的搜索，或检索前用策略引擎展开允许的 `doc_id` 列表（注意列表过大时的性能）。

**Q：缓存会不会穿权？**  
A：会。语义缓存 key 必须纳入用户权限语境，或只缓存完全公开区。

**Q：引用回源链接怎么控？**  
A：链接本身也要鉴权；不能生成永久公开 URL 给无权限用户。

| 取舍 | 实现快 | 安全强 |
|------|--------|--------|
| 后过滤 | 是 | 否 |
| 预过滤/隔离 | 工程量大 | 是 |
| 服务账号 | 省事 | 危险 |

## 身份下行

正确：`用户令牌 → 检索服务模拟用户身份 → 只搜可见集`  
错误：`服务账号搜全域 → 模型提示「别说出去」`

后者在日志、缓存、调试转储里仍可能泄漏。

## 多租户

物理隔离（每租户索引）简单粗暴；逻辑隔离（共享索引+强过滤）省成本但要强测试。金融/医疗偏前者更常见。
