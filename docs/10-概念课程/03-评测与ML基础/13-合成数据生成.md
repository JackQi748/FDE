# 合成数据生成

## 直觉

标注贵、稀有类少、隐私紧时，用模型/规则**合成**输入与标签扩集。合成能加速冷启动，也会制造**分布幻觉**：模型自己教自己，评测虚高，真实一碰就碎。

原则：合成是燃料，金标真值与线上抽检是锚。

## 讲解

### 常见路径

| 路径 | 做法 | 风险 |
|------|------|------|
| 模板槽位 | 规则填槽 | 多样性差 |
| LLM 改写/生成 | 种子题扩展 | 风格塌缩、泄漏 |
| 回译/增强 | 保义变换 | 语义漂移 |
| 模拟用户 | Agent 互搏 | 与真人差 |

质量闸：自动校验器（格式、一致性、可解性）+ 人工抽检 + **真持出集永不混入合成**。

训练用合成、报告用真数据——角色分离写进方案。

## 工作示例

权限拒答集不足：用政策条款生成 200 条应拒问法，人工抽 40 条修订；持出 30 条全真人撰写。合成仅进训练/提示开发。

污染实验：开发集掺 50% 合成后离线分大涨，真人持出不动——立刻降权合成。

## 面试取舍

取舍：速度 vs 可信。监管域慎用合成当验收。面试强调「锚」与泄漏（测试题进训练）。

## FDE用法

1. 合同写清合成数据是否允许、如何审计。
2. 流水线标记 `source=synthetic|human`。
3. 主指标只在 human/持出上宣称。

## 易混点

围绕「合成数据生成」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「合成数据生成」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。

## 面试 60 秒版本

「合成数据生成」我抓三件事：定义要可测、证据要可重复、上线要可控。我会先对齐业务代价，再选指标与门禁，用离线回归兜已知题，用金丝雀/影子控制爆炸半径，并把版本、成本、回滚写进同一张表。

- 能否用业务语言解释本主题解决什么问题？

- 是否区分离线可复现信号与线上真实行为？
- 是否准备至少一个反例说明何时不适用？

- 是否约定回归节奏与明确 owner？
- 是否避免只报单一总分，保留切片与错误本？
- 是否对标注/裁判做过抽检校准？
- 是否记录决策以便复盘？
