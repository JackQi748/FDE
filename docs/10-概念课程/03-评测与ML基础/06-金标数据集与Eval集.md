# 金标数据集与 Eval 集

## 直觉

金标（Golden Set）是「对这个客户而言什么叫好」的可执行定义：输入 + 期望（答案/引用/行为/量规分）+ 元数据切片。没有金标，项目只有表演；有金标，改动才能回归。

Eval 集可以多层：烟测集、开发集、持出验收集、对抗集、权限拒答集。

## 讲解

### 来源与分层

来源：历史真实查询（脱敏）、专家编写、故意难题、合规拒答、工具失败注入。

分层维度示例：意图、产品线、语言、是否需检索、是否需工具、风险等级、难度。

### 规模直觉

| 阶段 | 规模 | 用途 |
|------|------|------|
| 烟测 | 20–50 | PR 必跑 |
| Pilot | 100–300 | 门禁 |
| 生产核心 | 持续增长 | 发版回归 |

质量重于数量：错误标签比没标签更糟。建立标注指南与双人抽检。

### 与开发流程

内环用小集快速迭代；外环用持出+线上样本证明净赢。禁止把持出当调参盘。

## 工作示例

落地一周节奏：

1. Day1：从工单抽 80 条，粗标意图
2. Day2：专家按 0–2 量规打分，争议题写入指南
3. Day3：划 30 条持出，其余作开发
4. 每次改提示跑开发集；发版前跑持出+安全集

条目字段建议：

```text
id, input, expected_answer, must_cite_ids[],
intent, risk, should_refuse, notes
```

失败分析：每周把失败例归类进错误本，并回灌金标。

## 面试取舍

取舍：金标太小→过拟合；太大→标注崩、迭代慢。FDE 常用「核心硬集 + 轮换扩展集」。

面试强调：金标是合同语言的一部分——通过线、抽样方法、谁有权改标签。

## FDE用法

1. PoC→Pilot 门禁必须带初步 eval（哪怕 20–50）。
2. 客户签字的量规与通过线进 SOW/附录。
3. 标签变更版本化；指标对比注明金标版本。
4. 高风险域保留人类抽检预算。

## 速查清单

交付或面试前快速自检：

- 能否用业务语言解释「金标数据集与 Eval 集」解决什么问题？
- 是否写清成功指标、失败定义与不可接受副作用？
- 是否区分离线可复现信号与线上真实行为？
- 是否准备至少一个反例说明何时不适用？
- 是否把成本、延迟、风险与可运维性写入权衡表？
- 是否约定回归节奏与明确 owner？
- 是否避免只报单一总分，保留切片与错误本？
- 是否对标注/裁判做过抽检校准？
- 是否记录决策以便复盘（ADR/周报）？

- 本周失败例是否挑战了相关假设？

> 原创概念笔记：金标数据集与 Eval 集。

## 易混点

围绕「金标数据集与 Eval 集」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「金标数据集与 Eval 集」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。
