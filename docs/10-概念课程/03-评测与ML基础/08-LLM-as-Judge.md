# LLM-as-Judge（模型裁判）

## 直觉

开放生成难以精确匹配，于是用强模型按**量规（rubric）**打分或两两比较。裁判扩展人的判断，不替代高风险终审。

核心风险：位置偏、冗长偏、自我偏好、量规含糊导致人也不一致。

## 讲解

### 模式

| 模式 | 做法 | 适用 |
|------|------|------|
| Pointwise | 单输出按维度打分 | 监控、回归 |
| Pairwise | A vs B 选更好 | 选型、提示对比 |
| 多裁判投票 | 降低单模偏 | 重要发版 |

### 校准流程（背诵版）

1. 采样真实输出
2. 人类专家用同一量规打分
3. 算人机一致率（对照「人际一致」上限）
4. 分歧→改量规/换裁判提示或模型
5. 高风险档始终人工

文献经验：强裁判可接近人际一致，但仍有系统偏差，必须抽检。

## 工作示例

量规示例（RAG 答案 0–2）：

- 2：正确且证据恰当
- 1：部分正确或缺引用
- 0：错误、有害或该拒不拒

实验：提示 v1 vs v2，pairwise 胜率 58%，但人工抽 50 条一致仅 62%→先修量规「何谓恰当证据」，再重赛。

防位置偏：随机交换 A/B 顺序，不一致则标「平局/重判」。

## 面试取舍

| 选择 | 理由 |
|------|------|
| 上裁判 | 规模化、迭代快 |
| 不上 | 域极专、错判代价极高且无校准预算 |

面试忌：把裁判分当真理。宜说：校准、偏差、人工抽检比例。

## FDE用法

1. 裁判提示与量规版本化入库。
2. 每周固定抽检配额；一致率跌破阈值则停用自动门禁。
3. 与双环结合：内环可激进用裁判，外环验收混入人工。

> 原创概念笔记：LLM-as-Judge（模型裁判）。

## 易混点

围绕「LLM-as-Judge（模型裁判）」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「LLM-as-Judge（模型裁判）」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。
