# 校准与不确定性

## 直觉

**校准**：当模型说「70% 把握」时，长期看是否大约 70% 真对。准确但狂妄、或正确但过度不敢说，都会害决策。

不确定性分：**偶然不确定**（数据噪声）与**认知不确定**（模型没见过）。RAG 缺证据时应表现为高不确定并拒答/升级，而不是流畅瞎编。

## 讲解

### 度量

- Reliability diagram：置信桶 vs 实际命中率
- ECE（Expected Calibration Error）：桶偏差加权平均
- Brier score：概率预测综合分

分类可用温度缩放（temperature scaling）在验证集上拟一个 T；树模型可用 isotonic。生成式模型的「自报置信」常不准，需要外部信号：检索分、自评一致性、工具校验。

### LLM 实用代理

| 信号 | 用法 | 局限 |
|------|------|------|
| 检索 top 分差距 | 低差距→不确定 | 分位点需标定 |
| 多次采样一致率 | 低一致→谨慎 | 成本×N |
| 是否含引用 | 无引用降权 | 假引用 |
| 裁判置信 | 辅助 | 需校准 |

## 工作示例

工单优先级分类：输出 P(高)。上线后发现报 0.9 的样本只有 0.6 真高——ECE 差。

处置：

1. 在验证集学 temperature T
2. 决策阈值按代价重选
3. 对 ECE 差的切片（新业务线）单独模型或规则

RAG：若 top1 与 top2 余弦分差 < τ，强制「我不确定，已升级人工」。

## 面试取舍

面试点：会背 ECE 不如会说「高风险动作必须独立校验，不能信自报置信」。

取舍：多次采样估不确定更稳但贵；温度缩放便宜但假设输出是真概率。

## FDE用法

1. 自动执行路径设「置信+规则」双闸。
2. 看板同时看准确率与 ECE/升级率。
3. 教客户：流畅≠可信；展示引用与不确定态。

> 原创概念笔记：校准与不确定性。

## 易混点

围绕「校准与不确定性」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「校准与不确定性」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。

## 面试 60 秒版本

「校准与不确定性」我抓三件事：定义要可测、证据要可重复、上线要可控。我会先对齐业务代价，再选指标与门禁，用离线回归兜已知题，用金丝雀/影子控制爆炸半径，并把版本、成本、回滚写进同一张表。
