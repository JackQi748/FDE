# A/B、金丝雀与影子测试

## 直觉

上线新策略有三种常见「曝光控制」：**A/B** 把用户流量分开比指标；**金丝雀** 先放小比例真实流量观察；**影子** 新系统跟读流量但不影响用户，只对比输出。

目的都是：在不确定下控制爆炸半径，并拿到可归因证据。

## 讲解

### 对比

| 模式 | 用户可见 | 主要风险 | 适合 |
|------|----------|----------|------|
| A/B | 是 | 指标吵、伦理/业务约束 | 产品体验优化 |
| 金丝雀 | 部分是 | 仍有真实伤害 | 渐进发布 |
| 影子 | 否 | 成本双跑；行为不一致难比 | 高风险替换 |

LLM 特殊点：输出随机、延迟尾部、成本不对称；要固定种子或不比字面比量规分；监控 P95/P99 与 $/请求。

### 统计直觉

先定最小可检测效应与样本量；AI 项目常因样本不足「假胜利」。护栏指标（安全、投诉）用更敏感的停损规则。

## 工作示例

替换提示 v2：

1. 影子一周：记录 v1/v2 裁判分与人工抽检
2. 金丝雀 5%→20%：盯升级率、错误工单
3. 全量前确认成本不超预算

回滚开关：特征旗标 + 旧提示版本 + 旧索引别名。

## 面试取舍

| 场景 | 更优模式 |
|------|----------|
| 合规高风险 | 影子→小金丝雀 |
| 文案/UX | A/B |
| 基础设施替换 | 金丝雀+错误预算 |

忌：无停损的「先全量再说」。

## FDE用法

1. 发布清单含：指标、护栏、样本量、回滚 owner。
2. 与客户同步「实验期可能波动」。
3. 影子对比对齐同一请求 id。

> 原创概念笔记：A/B、金丝雀与影子测试。

## 易混点

围绕「A/B、金丝雀与影子测试」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「A/B、金丝雀与影子测试」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。

## 面试 60 秒版本

「A/B、金丝雀与影子测试」我抓三件事：定义要可测、证据要可重复、上线要可控。我会先对齐业务代价，再选指标与门禁，用离线回归兜已知题，用金丝雀/影子控制爆炸半径，并把版本、成本、回滚写进同一张表。
