# 精确率、召回率与 F1

## 直觉

**精确率（Precision）**：你报出来的里头，有多少是真的。**召回率（Recall）**：所有真的里头，你抓回来多少。**F1**：二者的调和平均，惩罚「只刷一个很高」。

医疗漏诊怕低召回；垃圾过滤误杀怕低精确。FDE 场景里：权限拒答、敏感检出、工单路由、实体抽取，都必须先问「错报与漏报哪个更贵」。

## 讲解

### 混淆矩阵四格

|  | 预测正 | 预测负 |
|--|--------|--------|
| 真金正 | TP | FN（漏报） |
| 真金负 | FP（误报） | TN |

- Precision = TP / (TP+FP)
- Recall = TP / (TP+FN)
- F1 = 2PR/(P+R)

多分类可 macro（各类先算再平均）或 micro（先汇总 TP/FP/FN）。类别极不平衡时，macro 更能暴露稀有类崩溃；micro 接近整体准确率口径。

### 阈值与 PR 曲线

概率模型输出分数后，阈值上移 → 精确率往往升、召回降。不要默认 0.5；应按业务代价选点，或报告 PR-AUC。

### 与生成式任务的关系

开放问答难做严格 TP/FP；但**结构化抽取、引用是否命中金标段落、工具是否该调用**仍可落成集合匹配的 P/R/F1。

## 工作示例

示例：合同条款抽取「终止通知天数」。金标 100 份合同含该字段。

- 系统抽出 80 次，其中 70 正确 → P=70/80=87.5%，R=70/100=70%，F1≈77.8%
- 产品经理只看「准确率 95%」（含大量无该字段的负例）会误判健康

RAG 引用评测：把「应引用的 chunk id 集合」当金标，对预测引用集合算 F1，比只看答案字符串更稳。

## 面试取舍

| 优化目标 | 典型场景 | 风险 |
|----------|----------|------|
| 高召回 | 安全检出、合规扫描 | 人工复核成本升 |
| 高精确 | 自动执行、对外发送 | 漏掉关键 case |
| 高 F1 | 均衡汇报 | 掩盖代价不对称 |

面试加分：主动问代价矩阵；提出「两阶段」——高召回召回器 + 高精确复核器。

## FDE用法

1. 和客户一起填「漏报/误报哪类事故更贵」，再定阈值。
2. 验收报表禁止只给 Accuracy；至少 P/R/F1 + 切片。
3. Agent 工具调用：对「该调未调 / 不该调却调」分别建混淆矩阵。
4. 金标变更时重算基线，避免指标漂移被当成模型变强。

## 速查清单

交付或面试前可快速过一遍：

- 能否用一句话向非技术干系人解释「精确率、召回率与 F1」解决什么问题？
- 是否写清成功指标、失败定义与不可接受的副作用？
- 是否区分「离线可复现信号」与「线上真实行为」？
- 是否准备了至少一个反例，说明该手段何时不适用？
- 是否把成本、延迟、风险与可运维性写进同一张权衡表？
- 是否约定了回归节奏（每次改动 / 每日 / 发版）？
- 是否指定 owner：谁看数、谁拍板上线、谁负责回滚？
- 是否避免只报单一总分，而保留分层切片与错误本？
- 是否对标注质量与裁判校准做过抽检？
- 是否把本次决策记入 ADR 或周报，便于复盘？

## 常见追问（简答）

**Q：为什么 FDE 要懂精确率、召回率与 F1？**  
A：因为客户买的是可运营结果，不是单次 demo；概念决定你如何设门禁与沟通风险。

**Q：最小可行落地是什么？**  
A：固定一小撮金标例 + 一个可重复脚本 + 一张权衡表 + 明确的通过线。

**Q：最容易踩的坑？**  
A：用公开榜或主观感觉替代客户域评测；或同时改十个变量导致无法归因。

## 易混点

围绕「精确率、召回率与 F1」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。
