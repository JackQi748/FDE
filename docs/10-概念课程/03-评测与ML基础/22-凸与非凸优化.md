# 凸与非凸优化

## 直觉

**凸**问题：局部最优即全局，形状像碗。**非凸**：多峰多鞍，深度网络属此类，却常能训到可用解。工程关心：初始化、步长、景观是否「足够友好」。

## 讲解

### 含义

- 凸：逻辑回归、某些 SVM 对偶——可强保证
- 非凸：深度网、矩阵分解——靠启发式与大量实践

鞍点多于坏局部极小的现代观点，解释了为何 SGD 噪声有帮助。但**可训≠已最优**，仍要验证集与多种子。

## 工作示例

同一 MLP 三种子，F1 差 3 个点——报告均值±方差，而不是单次高峰。

## 面试取舍

面试：不必证定理，要说明「无全局保证时如何用评测与复现约束风险」。

## FDE用法

1. 重要结论多种子/多数据折。
2. 超参搜索预算写进计划。

## 易混点

围绕「凸与非凸优化」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「凸与非凸优化」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。

## 面试 60 秒版本

「凸与非凸优化」我抓三件事：定义要可测、证据要可重复、上线要可控。我会先对齐业务代价，再选指标与门禁，用离线回归兜已知题，用金丝雀/影子控制爆炸半径，并把版本、成本、回滚写进同一张表。

## 速查清单

- 能否用业务语言解释本主题解决什么问题？
- 是否写清成功指标、失败定义与不可接受副作用？
- 是否区分离线可复现信号与线上真实行为？
- 是否准备至少一个反例说明何时不适用？
- 是否把成本、延迟、风险与可运维性写入权衡表？
- 是否约定回归节奏与明确 owner？
- 是否避免只报单一总分，保留切片与错误本？
- 是否对标注/裁判做过抽检校准？
- 是否记录决策以便复盘？
- 是否准备回滚或降级路径？
