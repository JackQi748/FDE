# 多臂老虎机（Bandits）

## 直觉

多臂老虎机处理「边赚边学」：**探索**未知臂 vs **利用**当前最优臂。比经典 A/B 更节省「已知更差选项」上的流量，但物理解释与长期因果更难点。

FDE 场景：提示/模型路由、推荐话术、阈值选择——在约束下自动倾斜流量。

## 讲解

### 算法直觉

| 算法 | 直觉 |
|------|------|
| ε-greedy | 以 ε 随机探索 |
| UCB | 乐观置信上界 |
| Thompson Sampling | 按后验采样选臂 |

上下文老虎机（contextual）把用户/查询特征纳入；更贴近真实，但工程复杂。

### 与 A/B 边界

- 需要干净因果结论、监管审计 → 偏 A/B
- 臂多、想尽快减伤 → 偏 bandit
- 奖励延迟大（次日投诉）→ bandit 难，需代理奖励

## 工作示例

三模型路由：cheap / mid / strong。奖励=任务成功 - λ·成本。

Thompson Sampling 每周更新成功/失败计数；强约束：安全失败不得自动加流量。

伪代码概念：

```python
for req in traffic:
    arm = sample_thompson(posteriors)
    reward = execute(arm, req)  # 0/1 或整形
    update(posteriors[arm], reward)
```

## 面试取舍

面试说清：奖励定义=产品定义；错奖励会优化到废话套话。取舍是速度 vs 可解释因果。

## FDE用法

1. 先影子估计奖励，再小流量 bandit。
2. 保留人工配额臂（专家策略）作安全底板。
3. 成本与安全作为硬约束，而非只进奖励标量。

## 易混点

围绕「多臂老虎机（Bandits）」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「多臂老虎机（Bandits）」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。
