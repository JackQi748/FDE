# 过拟合与正则化

## 直觉

过拟合=把训练细节（含噪声）背下来，换分布就崩。**正则化**是任何「限制假设空间或训练过程」的手段：L2、Dropout、早停、数据增强、权重衰减、提示里少写死特例、检索只留 top-k 等。

对 LLM 应用：过拟合经常发生在**评测集与提示**上，而不只在梯度更新里。

## 讲解

### 经典正则

| 方法 | 机制 | 备注 |
|------|------|------|
| L2/权重衰减 | 惩罚大权重 | AdamW 正确实现关键 |
| Dropout | 训练时随机掐神经元 | 推理关闭 |
| Early stopping | 验证最优处停 | 简单强 |
| 数据增强 | 扩分布 | NLP 增要谨慎语义 |
| 标签平滑 | 软化 one-hot | 常改善校准 |

### LLM/RAG 场景的「隐式正则」

- 缩短提示、减少特例列表
- 温度不要为刷题降到 0 又在线上开高
- 金标与开发集分离；禁止对着持出集调参
- 检索阶段用多样性约束，避免只拟合高频文档

## 工作示例

案例：分类微调。

- 无正则：epoch=10，train F1=0.99，val F1=0.71
- +早停(epoch=3) +权重衰减：train 0.90，val 0.81
- +稀有类过采样：稀有类 val +0.09，整体微降 0.01——按业务接受

提示过拟合实验：

1. 开发集 40 条上反复改提示到 95%
2. 冻结提示，跑从未看过的 40 条 → 68%
3. 结论：需要更大分层金标，而不是继续堆特例

## 面试取舍

| 手段 | 收益 | 成本 |
|------|------|------|
| 早停 | 便宜 | 要可靠验证集 |
| 更大更干净数据 | 往往最强 | 贵、慢 |
| 强正则 | 稳 | 可能欠拟合 |
| 对着测试集调 | 「分很高」 | 面试/交付双杀 |

说出「我们把测试集锁住，调参只用开发集」是强信号。

## FDE用法

1. 建立 train/dev/test（或金标开发/持出）纪律。
2. 提示变更也当「训练」：限制调参轮数与查看持出次数。
3. 生产监控分布漂移，过拟合常以「新意图崩」显现。

---

> 原创概念笔记：过拟合与正则化。

## 易混点

围绕「过拟合与正则化」，现场最常见的概念混淆：

1. **把代理指标当成业务结果**：技术分上涨不等于采纳、周期或风险下降。
2. **只看平均、不看切片**：整体健康时，高风险长尾可能已经崩盘。
3. **同时改多个旋钮**：无法归因，复盘只能靠叙事。
4. **忽略标注/量规版本**：指标不可比，却被讲成「模型变强」。
5. **缺乏回滚故事**：说得清正向收益，说不清如何止损。

## 指标与日志建议

若要把「过拟合与正则化」落到可运营状态，最少保留：

| 字段/信号 | 用途 |
|-----------|------|
| request_id / trace_id | 对齐离线、影子与在线 |
| 策略/模型/提示版本 | 归因与回滚 |
| 自动分 + 人工抽检标记 | 校准与审计 |
| 延迟分位与成本 | 防止质量优化打爆预算 |
| 错误类标签 | 驱动错误本与金标回灌 |

日志要能回答：哪次改动、对哪类用户、在哪一环坏了。

## 反模式

- 用公开 Benchmark 替代客户域金标，还把名次写进验收。
- 在持出集上反复调参，再宣称泛化良好。
- 只有开心路径 demo，没有拒答、权限、工具失败注入。
- 汇报时隐藏置信区间与样本量。
- 让业务方「凭感觉」改通过线，而不改量规文本。

## 一周落地节奏（示例）

| 日 | 动作 |
|----|------|
| D1 | 写清问题、代价、成功定义；找到数据主人 |
| D2 | 搭最小可重复脚本与基线分 |
| D3 | 分层抽样补强；标注重争议题 |
| D4 | 做一次单变量改进并对比 |
| D5 | 复盘失败类；更新错误本与门禁 |

若五天内无法复现基线，优先修数据与工程，而不是换更大模型。
