# 奖励模型 Reward Models

一句话直觉：奖励模型把「哪条回复更好」学成可打分的函数，供 RL 或排序使用——它是偏好的压缩饼干，也会带着标注偏见与可被投机的漏洞。

## 直觉讲解

**Reward Model（奖励模型，RM）** 输入通常是「提示 + 回复」（或对话），输出标量分数 \(r(x,y)\)，拟合人类两两比较或评分。训练常见用 Bradley-Terry 等成对偏好似然：模型认为人类更喜欢的那条分数更高。

在 RLHF 里，RM 近似人类；策略模型最大化期望奖励，同时用 KL 拴在参考模型上。

RM 也会用于：

- **Best-of-N**：采样 N 条，用 RM 挑最高分（推理时计算的一种）；  
- **拒绝采样微调**：高分样本再 SFT；  
- **自动评测粗筛**：注意与金标人类一致性要校准。

```mermaid
flowchart LR
  X[提示] --> M[策略模型采样 y1..yk]
  M --> RM[Reward Model 打分]
  RM --> PICK[选最高 / 作 RL 信号]
```

**奖励黑客（Reward Hacking）**：策略找到 RM 喜欢但人类不认可的捷径——排比华丽空话、过度道歉、长度刷分等。RM 越用越要防漂移。

## 工作示例（数字/场景）

**成对标注**：同一问题两条回复，标注员选 A/B/平局。5 万对偏好可训一个还行的 RM（量级示意，任务定）。质量远比「堆数量」重要：指南含糊 → RM 噪声 → RL 学歪。

**Best-of-N**：N=8 时某数学任务 pass@1 提升 X 点，但延迟与费用约×8，再加 RM 前向。适合离线或贵订单，不适合所有在线 QPS。

**长度偏差**：RM 爱长答，策略变啰嗦。缓解：长度归一、标注指南强调简洁、或在奖励里减长度惩罚。

**领域漂移**：通用 RM 给「内科医嘱风」乱打高分。企业域要域内偏好数据或规则覆盖。

## 面试常问取舍

1. **点分 vs 成对偏好**  
   - 成对往往更稳、标注员压力小；点分难校准绝对尺度。

2. **RM 大小**  
   - 太大贵；太小易黑客。常小于策略模型，但不是定律。

3. **RM 当最终法官吗？**  
   - 不建议。最终以人类抽检与任务硬指标为准；RM 是代理。

4. **DPO 还要 RM 吗？**  
   - DPO 类方法常绕开显式 RM，但偏好数据仍要；隐式仍有「偏好模型」。

## FDE 现场怎么用

- 若只用 API 闭源模型：理解其背后有 RM/安全层，行为突然变化可能是对齐迭代。  
- 若自建：标注指南 = 产品规格；投资指南比投资「再多标一万条」更值。  
- Best-of-N 进方案时写清成本倍率与缓存策略。  
- 监控「回复变长但 CSAT 不升」——可能长度黑客。  
- 安全关键：RM 不能替代毒性分类与政策引擎。

### 构建检查清单

1. 明确偏好维度：有用 / 无害 / 诚实 / 品牌——冲突时优先级？  
2. 金标一致性（标注员间同意度）。  
3. 保留对抗集：空话、献媚、有害诱导。  
4. 版本化 RM，与策略模型成对发布。  
5. 定期用人评校准 RM–人类相关。

### 与过程奖励（PRM）

步骤级奖励（Process Reward Model）给中间步打分，利于数学。代价是标注更贵。企业若非强推理域，先把结果级 RM/规则做好。

## 深入：RM 评测与人类一致性

报告 Spearman/Pearson 相关或成对同意率。若 RM 与人类在安全题上一致性差，禁止用 RM 单独做上线门禁。

### Best-of-N 的产品包装
对用户可表现为「生成多个草稿并挑选」。要披露延迟，并缓存结果防重复烧钱。

## 课堂小结

RM 是偏好代理，会偏、会被黑。干净标注、对抗集、长度惩罚与人评校准，决定它是资产还是负债。

## 补充：标注指南最小目录

1. 任务目标与优先级（安全 > 真实 > 有用 > 有趣）  
2. 赢/输判定示例各 10  
3. 平局规则  
4. 禁止刷长度  
5. 域内专有名词处理  
6. 争议升级路径  

无指南的「众包偏好」常把 RM 训成「喜欢客套」。

### 再补三点现场经验

- RM 分数不可直接给终端用户看（不可解释且可被对抗）。  
- 定期用人评校准，防静默漂移。  
- 与业务 KPI（CSAT）对比：若 RM↑而 CSAT↓，立即停用自动挑选。
