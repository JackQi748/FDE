# POC 验收表

用于 **PoC → Pilot** 门禁。填写版：[templates/POC验收表.md](../templates/POC验收表.md)。  
理论见 [POC 到生产](../02-交付方法论/POC到生产.md)。

---

## 1. 为什么需要验收表

没有门禁，Demo 欢呼会被当成「可以推广」。验收表把「技术可行」与「业务可试点」写成**可勾选证据**，并留下 Go/No-Go 书面记录。

---

## 2. 最小检查项

| ID | 项 | 通过标准 | 证据示例 |
|----|----|----------|----------|
| P1 | 问题陈述确认 | 赞助人邮件/纪要确认 | 链接 |
| P2 | 目标环境路径 | 非仅笔记本；网络/驻留可行 | 拓扑一页纸 |
| P3 | 安全初审 | 数据流与权限草图已阅 | 评审纪要 |
| P4 | 初步 Eval | 冻结集上达到约定线，或诚实未达线 | 跑分报告 |
| P5 | 试点范围 | 用户×内容×时间盒书面化 | 范围一页纸 |
| P6 | 风险与缓解 | Top3 有负责人 | 风险表 |
| P7 | Owner | 客户侧对接人指名 | 姓名角色 |
| P8 | Go/No-Go | 书面决策 | 决策备忘录 |

未通过则不得宣称「可推广到全员/生产」。

---

## 3. 怎么开 Go/No-Go 会（30 分钟）

1. 逐项看证据（15）——无链接算 Fail  
2. 红灯项讨论是否「有条件通过」（10）  
3. 记录决策与条件到期日（5）  

有条件通过必须写清：条件是什么、谁负责、最晚何时，否则等于没门禁。

---

## 4. 常见扯皮与应答

| 说法 | 应答 |
|------|------|
| 「领导看了 Demo 很满意」 | Demo ≠ P4 Eval；补冻结集 |
| 「环境下周一定好」 | P2 未过就维持 PoC，不进 Pilot |
| 「安全太慢」 | 升级赞助人；给最小开通清单 |
| 「先上再补文档」 | 门禁就是防这个；书面 No-Go 或缩范围 |
