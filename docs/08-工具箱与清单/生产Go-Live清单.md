## 1. 摘要门禁（开会用）

### 可靠性与运营

- [ ] 降级与回滚演练过（记下时间与结果）  
- [ ] 看板与告警指向真实值班人  
- [ ] Runbook 已交客户并可打开  

### 安全

- [ ] SSO/ACL 强制验证通过（含跨用户用例）  
- [ ] 密钥与 PII 策略就绪  
- [ ] 审计日志可查  

### 质量

- [ ] Eval 回归通过线（附报告链接）  
- [ ] 已知限制对用户可见（UI 或文档）  

### 采用

- [ ] 培训完成，材料可查  
- [ ] 支持渠道与升级路径明确  
- [ ] 客户侧 Owner 指名  

### 决策

- [ ] Go / 有条件 Go / No-Go 书面记录  

---

## 2. 「有条件 Go」怎么写才有效

```text
条件：完成 X
负责人：Y
最晚：日期
到期未完成：自动降级为 No-Go / 维持 Pilot
```

没有到期日的条件 = 永远的灰色生产。

---

## 3. Go-Live 当天与之后 72 小时

| 时间 | 动作 |
|------|------|
| 当天 | 变更窗口内发布；验证主路径；公告边界 |
| 24h | 看错误率/成本/负反馈；热修或回滚 |
| 72h | 短复盘：是否误判门禁；补 Runbook |

---

## 5. 会上红灯话术

| 红灯 | 推荐说法 |
|------|----------|
| Eval 未过线 | 「建议 No-Go 或缩范围；强推会破坏信任」 |
| 回滚未演练 | 「有条件 Go：48h 内完成演练，否则自动撤回」 |
| Owner 未指名 | 「没有客户 Owner 就不进生产支持」 |
| 安全未批 | 「维持 Pilot；并行最小开通清单」 |
