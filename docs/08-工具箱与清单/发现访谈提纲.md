# 发现访谈提纲

配合 [需求发现与问题拆解](../02-交付方法论/需求发现与问题拆解.md)、[咨询思维与软技能栈](../02-交付方法论/咨询思维与软技能栈.md)。  
访谈后把答案写入 [templates/发现访谈纪要.md](../templates/发现访谈纪要.md)。

---

## 1. 会前准备

- [ ] 明确受访者角色（一线用户 / 赞助人 / IT / 安全 / 法务）  
- [ ] 查清他被什么指标考核（若可知）  
- [ ] 征求是否可旁看真实系统/工单（脱敏）  
- [ ] 准备开场：「我不是来推销功能，是来理解你们怎么工作」  
- [ ] 预留 45–60 分钟；超时不如约第二次  
- [ ] 带纸笔或可共享的空白问题陈述草稿  

**不同角色侧重点**

| 角色 | 多问 | 少问 |
|------|------|------|
| 一线 | 步骤、耗时、例外、工具来回 | 战略口号 |
| 赞助人 | 成功叙事、预算窗口、政治 | 过细 API |
| IT | 集成、账号、环境、变更窗口 | 「你们能不能快点」 |
| 安全/法务 | 分级、驻留、审计、否决权 | 模型参数细节 |

## 2. 访谈问题（按需取舍）

### A. 工作流（必问）

1. 请带我走一遍**最近一次真实**处理过程（不要理想流程）。  
2. 哪些步骤最耗时？哪些最易错？  
3. 用到哪些系统？哪里要来回复制粘贴？  
4. 有没有「只有老人知道」的例外规则？  

### B. 成功标准

5. 你的上级用什么数字看这个团队？  
6. 若只能改善一件事，选哪件？为什么？  
7. 怎样算试点成功？怎样算失败该停？  
8. 有没有基线数字（哪怕粗糙）？  

### C. 风险与约束

9. 最近一次严重失误的后果是什么？谁承担责任？  
10. 数据能否出内网？有哪些合规要求？  
11. 谁有权否决上线？历史上否决过类似项目吗？  
12. 答错/漏做的「不可接受」边界在哪？  

### D. 组织与变更

13. 谁会日用？谁只是「听说要 AI」？  
14. 过去类似工具为什么失败或停用？  
15. 培训与变更窗口有什么限制？  
16. 你离开两周，谁能当内部 Champion？  

### E. 数据与系统（偏 IT）

17. 权威源（System of Record）是哪个系统？  
18. 刷新频率与质量已知问题？  
19. 现有身份与权限模型（SSO/角色/文档 ACL）？  
20. 有没有可用的非生产环境与样例数据？  

---

## 3. 追问句式（好用）

- 「能否打开系统让我看一眼刚才说的那条？」  
- 「如果答案错了但看起来很像样，会发生什么？」  
- 「为什么是现在做？三个月前为什么没做？」  
- 「若试点只给你们组 20 人，你选谁先进来？」  

---

## 4. 会中记录技巧

- 区分：**原话** vs **你的推断**（推断要标注）  
- 听到解决方案（「我们要个 Chatbot」）立刻爬回结果指标  
- 冲突观点并记，不现场站队  
- 结束前复述问题陈述草稿，请对方纠正  

---

## 5. 会后 24 小时内

- [ ] 发出纪要，请对方确认问题陈述  
- [ ] 列出开放问题与下一步时间盒  
- [ ] 更新风险登记（含组织风险）  
- [ ] 若发现「数据两周后才好」等红旗 → 升级赞助人  

红旗列表见 [咨询思维](../02-交付方法论/咨询思维与软技能栈.md)。

---

## 6. 读完马上做

- [ ] 选一个虚构客户，写出 8 个你会问的问题  
- [ ] 用模板填一篇模拟纪要
