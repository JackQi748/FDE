# 变更管理与培训设计进阶

技术门禁通过后，**采用**仍可能失败：系统能跑，但没人用、或用了更慢、或用错出事故。本篇把变更管理做成可执行设计，而不是「发个上线通知」。

衔接：[POC 到生产](../02-交付方法论/POC到生产.md)、[客户沟通](../02-交付方法论/客户沟通与阻力处理.md)、[解决方案产品化](./解决方案产品化.md)。

---

## 1. 变更的本质

你要求用户改变习惯。阻力通常来自：

- 多一个入口 / 多一步操作  
- 怕错、怕被追责、怕 AI「黑箱」  
- 考核与新旧流程冲突  
- 旧流程里有灰色空间（AI 一透明就暴露）  
- 「又一个虎头蛇尾的数字化项目」的历史创伤  

FDE 管理的是**行为变化与组织条件**，不是功能列表。

---

## 2. 变更设计画布（立项时就填）

| 块 | 问题 | 产出 |
|----|------|------|
| 受众分段 | 谁是日用/偶用/否决者？ | 分段名单与人数 |
| 价值主张 | 每人多得到什么、少失去什么？ | 一句话/角色 |
| 工作流嵌入 | 是否出现在原系统里？ | UX 决策（侧栏 vs 新站） |
| 激励与考核 | 是否与 KPI 冲突？ | 与管理者对齐记录 |
| 能力建设 | 需要什么技能？ | 培训大纲 |
| 支持 | 前两周谁答疑？ | 值班表与渠道 |
| 反馈 | 错误如何进系统改进？ | 上报 → Eval 路径 |
| 成功叙事 | 四周后讲什么故事？ | 指标 + 用户引言 |

**没填画布就上线** ≈ 赌运气。

---

## 3. 受众分段与差异化沟通

| 分段 | 他们在乎 | 你提供 |
|------|----------|--------|
| 一线日用 | 省事、少挨骂 | 嵌入原工具、清晰升级路径 |
| 基层主管 | 团队产出与差错 | 看板、抽检口径 |
| 赞助人 | 叙事与 ROI | 周报指标、风险选项 |
| IT/安全 | 稳定与合规 | 数据流、权限、回滚 |
| 否决者 | 风险与职责 | 书面边界、HITL、审计 |

同一套功能，对外口径可以不同，但**事实必须一致**（尤其能力边界）。

## 4. 培训设计（够用即可）

### 30–45 分钟上手课结构

| 分钟 | 内容 | 目的 |
|------|------|------|
| 5 | 解决什么 / 不解决什么 | 管预期 |
| 10 | 主路径现场演示 | 建立「能用」 |
| 5 | **故意演示失败与如何升级** | 建立信任（关键） |
| 15 | 学员实操 2 个真实工单 | 肌肉记忆 |
| 5 | 支持渠道与考核说明 | 降低焦虑 |
| 5 | 问答 | 收尾 |

### 材料包（最低配）

- 一页速查（截图 + 三步）  
- 3 分钟录屏（可反复看）  
- FAQ：含「AI 错了怎么办」「哪些不能问」  
- 管理员 Runbook：停用开关、回滚、联系人  

### 培训反模式

- 只讲模型多强，不讲边界  
- 只演示甜例，不演示失败  
- 培训完没有支持频道，问题进私人微信失踪

## 5. 采用曲线运营（上线 14 天）

| 日 | 动作 | 产出 |
|----|------|------|
| 0 | 上线；冠军用户启动；公告边界 | 冠军名单 |
| 1–3 | 每日答疑；收集前 20 个摩擦点 | 摩擦看板 |
| 4–7 | 修 Top 摩擦；发变更日志 | 可见改进 |
| 8–14 | 看漏斗；访谈不采用者 | 去留决策输入 |
| 14 | Review：扩 / 停 / 改 | 书面结论 |

### 漏斗指标（建议）

`邀请 → 首次使用 → 当日完成主任务 → 周留存 → 建议采纳率/任务完成率 → 主动上报问题数`

只看 DAU 不够；FDE 更关心**任务是否完成、建议是否被采纳、差错是否下降**。

---

## 6. 与「抵抗」共处

| 现象 | 可能原因 | 动作 |
|------|----------|------|
| 注册不用 | 入口远、无价值、不信任 | 嵌回原工作台；找真痛；用冠军带 |
| 用后差评 | 慢、错、不会用 | 失败案例周复盘；补培训 |
| 阴奉阳违 | 考核冲突 | 与管理者改 KPI 或停项目 |
| 超级用户垄断 | 知识未扩散 | 轮值冠军；文档化；录屏 |
| 「还是用旧法」 | 旧法有灰色空间 | 别道德审判；先保证安全路径可用 |
| 放大单次事故 | 沟通缺位 | 诚实公告、根因、纠正措施 |

## 7. 沟通节奏建议

| 对象 | 节奏 | 内容 |
|------|------|------|
| 一线群 | 每日（首周） | 小技巧、已知问题、修复 |
| 业务主管 | 每双周 | 指标与摩擦 |
| 赞助人 | 里程碑 / 每周 | 选项式决策，不堆日志 |
| IT/安全 | 按变更 | 变更说明与回滚 |

模板：[周报](../08-工具箱与清单/周报模板.md)、[高管周报 WES](../templates/高管周报WES.md)。

## 8. 与解决方案产品化的衔接

每个成功试点至少沉淀：

1. 问题陈述模板  
2. 架构参考与非目标  
3. Eval 集种子  
4. 培训材料（本篇材料包）  
5. 门禁清单  
6. 已知限制与适用边界  

这就是「前线 → 可复制包」飞轮。详见 [解决方案产品化](./解决方案产品化.md)。

## 9. 合成小例子：坐席助手上线首周

- Day 0：只开两个班组；明确「不自动对外发送」  
- Day 1：发现入口藏在三级菜单 → Day 2 嵌到工单侧栏  
- Day 3：过期活动页导致错建议 → 加生效时间过滤 + 公告  
- Day 7：采纳率 22%→38%；培训补「如何一键负反馈」  
- Day 14：决定扩第三班组，仍不开全自动  

叙事给赞助人：指标 + 摩擦修复 + 明确仍不做的事。
