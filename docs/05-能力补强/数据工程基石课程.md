# 数据工程基石课程

> 整理并扩展自 Awesome Forward Deployment Engineering。  
> FDE 任务常从「数据审计」开始：理不清客户二十年的脏 schema，就无法在其上建 AI。

相关：[Snowflake/Databricks 现场](./Snowflake与Databricks现场.md)、[GCP 云架构](./GCP云架构与基础设施.md)、[限域数据分析助手](../06-行业案例/06-限域数据分析助手.md)。

## 1. 为什么是基石

前线很少从「完美数据湖」起步。你面对的是：

- 损坏或不一致的 schema  
- 影子 Excel / 个人 Access  
- 无主键、无更新时间的表  
- 「两周后数据就好」的承诺  

**第一周若建不成可信基线**，后面所有 RAG/Agent 都是沙上建塔。

## 2. 必掌握能力

### 2.1 高级 SQL 与查询调优

不止会 `JOIN`：

| 技能 | 现场用途 |
|------|----------|
| 窗口函数 | 「每个用户最新一条」、排名、滑动统计 |
| 递归 CTE | 组织树、账单层级 |
| `EXPLAIN` / 查询画像 | 为何扫了 10TB、该加分区还是改写法 |
| 分区/聚簇直觉 | 控制成本与延迟（仓型而异） |

**练习**：拿一份公开数据集，写「每客户最近一笔订单金额」并对比慢/快写法。

### 2.2 面向现实的数据建模

- **星型模型（Star）**：事实表 + 维度，分析友好  
- **一张大宽表（OBT）**：消费简单，刷新与一致性成本高  
- 明确 **System of Record（权威源）**，避免建在过期副本上  
- 为 AI 备数时：宁可要「窄而真」的主题域，不要「全家桶湖」  

### 2.3 Medallion（铜银金）

| 层 | 含义 | FDE 检查点 |
|----|------|------------|
| **Bronze** | 原始落地，尽量不可变 | 能否追溯回源文件/批次 |
| **Silver** | 清洗关联后的真相层 | 主键、去重、时钟、质量规则 |
| **Gold** | 业务就绪聚合 | 指标口径 owner 是谁 |

AI 检索常见接在 Silver/Gold 的受控视图上，而不是直接扫 Bronze 垃圾场。

### 2.4 分布式计算直觉

- Spark/Ray 分区与 shuffle  
- **Data Skew**：热点键把作业打爆  
- **OOM**：本地笔记本跑不动客户全量——改抽样、改仓内算、改作业  

你不需要天天写大型作业，但要能**听懂平台同学的诊断并一起改方案**。

### 2.5 数据质量与可观测

为数据做断路器：

- 新鲜度：迟到超过 SLA → 告警，看板打「数据过期」  
- 完整性：空值率骤升 → 阻断下游 Gold  
- 体积：行数暴跌 → 可能上游挂了  

原则：**CEO 看见坏数之前，你应先收到告警。**

## 3. 现场第一周建议动作

1. 画数据源地图：系统、刷新、owner、质量坑  
2. 抽样画像：空值、主键、时间戳、重复率  
3. 点名权威源 vs 影子 IT  
4. 定 Bronze→Silver 最小路径（一个主题域）  
5. 书面记下「两周后才有数」类风险并升级  

模板思路见 [现场勘察](../08-工具箱与清单/现场勘察与范围文档.md)。

---

## 4. 给 AI 项目的数据就绪检查

- [ ] 主题域表白名单与口径文档  
- [ ] 行/列级权限能否在仓或视图强制  
- [ ] PII 列是否识别并脱敏策略清晰  
- [ ] 有无非生产样例可安全开发  
- [ ] 刷新失败时 AI 侧降级策略  

---

## 5. 两周自学微路径（有 SQL 基础者）

| 天 | 动作 |
|----|------|
| 1–2 | 窗口函数专题 + 5 道业务题 |
| 3–4 | 对一份脏 CSV 做画像报告（空值/重复/类型） |
| 5–6 | 设计某业务的 Star 或 OBT，并写取舍 |
| 7–8 | 用 DuckDB 本地跑通 Bronze→Silver 小样例 |
| 9–10 | 写 3 条数据质量规则伪代码/SQL |
| 11–14 | 对接 [限域分析助手](../06-行业案例/06-限域数据分析助手.md) 思路，列金标问题 |
