# 零基础编程补课地图

给编程较弱、希望最终走上 FDE 路径的读者。目标是 **2–4 周达到能并入转岗 Week 2**，不是成为算法竞赛选手，也不是「学会所有框架」。

完整路径说明见 [学习路径-零基础](../00-导读/学习路径-零基础.md)。  
达标后进入 [学习路径-转岗者](../00-导读/学习路径-转岗者.md) 的 **Week 2（交付方法论）**。

---

## 0. 开始前：你其实要学会什么

FDE 现场最少需要这四块「动手能力」：

| 能力 | 最低标准 | 为何重要 |
|------|----------|----------|
| 读/写 Python 脚本 | 会函数、读写文件、处理 JSON | 胶水代码、评测脚本、小工具都靠它 |
| 调 HTTP API | 会带 Header 发请求、看状态码、解析响应 | LLM、业务系统、Webhook 全是 API |
| 管密钥与配置 | 密钥进环境变量，不进 Git | 客户环境第一道红线 |
| 用 Git 讲故事 | commit 清楚、README 能让别人跑起来 | 交接、协作、面试作品集 |

**刻意不做的事（前四周）**：刷算法题海、学 3 个 Agent 框架、配复杂前端、纠结 IDE 主题。

---

## 1. 学习原则

1. **每周必须有可运行产物**——没有产物的一周算没学  
2. **只深挖一条语言**：建议 **Python 3.11+**  
3. **先 API 与脚本，再框架**——HTTP + 文件比 LangChain 更本分  
4. **用 Git 管理一切**——从第一天 `git init`  
5. **每天限时 60–90 分钟**，周末加长做周产物；熬夜堆课不如稳定交付  
6. **写「我卡在哪」笔记**——卡点本身就是学习信号  

### 环境建议（任选其一即可）

- macOS / Linux：终端 + VS Code / Cursor  
- Windows：优先 **WSL2**，减少路径与命令差异  
- Python：官方安装或 `uv` / `conda` 任选，保持虚拟环境习惯  

```bash
# 示例：venv
python3 -m venv .venv
source .venv/bin/activate   # Windows WSL / macOS / Linux
pip install requests pandas
```

## 2. 四周大纲（可执行版）

### 第 1 周 — Python 与环境

**目标**：能独立写小脚本处理表格数据。

| 日 | 学什么 | 练习 |
|----|--------|------|
| 1 | 安装 Python、venv、pip；Hello World | 打印当前时间与工作目录 |
| 2 | 变量、类型、`if/for`、函数 | 写 `mean(nums)` |
| 3 | 列表/字典、异常 `try/except` | 统计词频（给一段文本） |
| 4 | 读写文本与 CSV（`csv` 或 `pandas`） | 读员工表，按部门计数 |
| 5–7 | 整理脚本 + README | **周产物**：`summary_csv.py` + 样例数据 + 运行说明 |

**周产物验收**

- [ ] `python summary_csv.py data/sample.csv` 能跑  
- [ ] 缺文件时有友好报错，而不是 Traceback 甩脸  
- [ ] README 写清：需要 Python 版本、如何建 venv  

**常见坑**

- 全局乱装包 → 一律进 venv  
- 中文路径/编码 → CSV 显式 `encoding="utf-8"`  

---

### 第 2 周 — HTTP API 与密钥

**目标**：安全地调用外部 API（含 LLM），并理解请求链路。

| 日 | 学什么 | 练习 |
|----|--------|------|
| 1 | HTTP 方法、状态码、JSON | 用 `curl` 或浏览器看一个公开 API |
| 2 | `requests`/`httpx`：GET/POST、超时、重试直觉 | 写 `get_json(url)` |
| 3 | Header、Bearer Token；环境变量 `os.environ` | 密钥放 `.env`（本地）或 shell export |
| 4 | `.gitignore` 忽略 `.env`、`.venv` | 故意「差点提交密钥」演练一次再撤销 |
| 5–7 | 对接任一 LLM API（按服务商 Quickstart） | **周产物**：`chat_once.py` 读问题、打印回复、打日志 |

**周产物验收**

- [ ] 仓库里**没有**真实密钥  
- [ ] 有 `.env.example`：`API_KEY=your_key_here`  
- [ ] 处理超时与非 200：打印状态码与响应摘要  
- [ ] README 写清费用与合规提醒（别拿客户数据去免费试用）  

**口述题（给自己录音 60 秒）**

> 「用户输入 → 我的脚本 → HTTPS → 模型商 → JSON 回来 → 我打印。密钥在环境变量，不进 Git。」

**常见坑**

- 把 key 写进代码再截图发群  
- 不设超时，请求挂死  
- 打印完整响应含敏感字段  

最小骨架示例（示意，非完整工程）：

```python
import os, requests

API_KEY = os.environ["API_KEY"]  # 缺失会 KeyError，可改成更友好提示
url = "https://api.example.com/v1/chat"  # 换成你的服务商地址
resp = requests.post(
    url,
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={"messages": [{"role": "user", "content": "你好"}]},
    timeout=30,
)
resp.raise_for_status()
print(resp.json())
```

### 第 3 周 — Git 与小项目结构

**目标**：项目能被「另一个人」按 README 跑起来。

| 日 | 学什么 | 练习 |
|----|--------|------|
| 1 | `init/status/add/commit/log` | 把第 2 周脚本纳入 Git |
| 2 | `branch`、查看 diff | 开分支改提示词再合并 |
| 3 | 远程：GitHub/Gitee 任选；`push` | 建私有库也行 |
| 4 | 项目结构：`src/`、`data/`、`README`、`requirements.txt` | 拆 `main.py` / `config.py` |
| 5–7 | 写给「陌生人」的 README | **周产物**：干净仓库 + 运行录屏或 GIF（可选） |

**推荐最小结构**

```text
my-fde-starter/
  README.md
  requirements.txt
  .gitignore
  .env.example
  src/
    main.py
    config.py
  data/
    sample.txt
```

**周产物验收**

- [ ] 克隆后按 README ≤5 步可运行（除申请自己的 API Key）  
- [ ] commit 信息能看懂（如 `add env-based api key loading`）  
- [ ] `.gitignore` 含 `.env`、`.venv`、`__pycache__/`  

**常见坑**

- 一次 commit 塞一周垃圾  
- README 只有「pip install 然后运行」却不写入口文件名

### 第 4 周 — 最小「知识问答」Demo

**目标**：做一个**故意简陋但诚实**的本地问答，并写清「离生产还差什么」。

两条路径（选一条做透）：

| 路径 | 做法 | 适合 |
|------|------|------|
| A. 手工增强 | 把相关段落粘进 prompt 再问 LLM | 最快建立直觉 |
| B. 关键词检索 | 本地切段 → 关键词打分取 Top-K → 塞进上下文 | 更接近 RAG 形状 |

**建议任务拆解**

1. 准备 5–10 篇本地 `.md`/`.txt`（可用公开制度样例，勿放真客户数据）  
2. 实现：输入问题 → 找出相关片段 → 调用 LLM → 输出答案 +「依据片段」  
3. 故意问一个**语料里没有**的问题，看会不会瞎编  
4. 写半页「生产差距清单」  

**周产物验收**

- [ ] Demo 可跑，且展示至少 1 次「应拒答/应说不知道」  
- [ ] 文档写明：无权限、无评测集、无观测、无成本控制  
- [ ] 对照 [生产化清单](../03-AI落地/生产化清单.md) 勾 5 条「还缺」  
- [ ]（加分）对照 [RAG 实战精要](../03-AI落地/RAG实战精要.md) 用自己的话写「我的 Demo 属于哪一层」  

**半页生产差距示例（可抄结构）**

```text
本 Demo 能证明：检索+生成比裸聊少一点胡说。
还不能上生产，因为：
1. 没有用户身份与文档 ACL
2. 没有冻结黄金集与回归
3. 密钥/日志未按企业规范
4. 没有 HITL 与升级人工
5. 成本与延迟未测量
下一步：先补 20 条黄金题，再谈框架。
```

## 4. 每日节奏模板（90 分钟）

| 块 | 分钟 | 做什么 |
|----|------|--------|
| 学 | 25 | 跟教程/文档过一个小概念 |
| 做 | 45 | 改自己的周产物代码 |
| 记 | 15 | 写：今天学会 / 卡点 / 明天第一刀 |
| 休 | 5 | 停。明天接着做，不熬穿  

连续 3 天卡住同一点：换资源或把问题拆更小，而不是「再看 10 个视频」。

## 5. 合流标准（进转岗 Week 2 前自检）

- [ ] 独立完成带密钥管理的 API 脚本  
- [ ] 会基本 Git（看 log、做一次有意义的 commit）  
- [ ] 能口述「请求从哪进、从哪出」  
- [ ] 知道幻觉是什么，以及为何需要评测  
- [ ] 有一个可演示的迷你项目（即使简陋）  
- [ ] 能指出该项目离生产的 5 个缺口  

**未达标时**：延长第 2–4 周，不要硬跳 Decomposition 面试训练——地基不稳，后面会反复返工。

## 6. 资源类型建议（不绑死单一课程）

| 主题 | 类型 | 备注 |
|------|------|------|
| Python | 官方 Tutorial | 稳定、少广告 |
| HTTP/JSON | MDN 或任意「HTTP 入门」 | 懂状态码即可 |
| Git | 官方 Pro Git 前几章 / 短视频 | 先会日常五命令 |
| LLM API | 所选模型商 Quickstart | 以官网为准，防过时 |
| 可选 | 《Automate the Boring Stuff》类 | 增强脚本直觉 |

本库不绑定付费课，避免链接腐烂；你选「能让你做出周产物」的那一套即可。

## 7. 进阶（可选，第 5–6 周）

若四周后仍有余力，再选 **一题**：

1. 给 Demo 加 20 条黄金问题（对/错/应拒答）  
2. 用 Docker 跑起来（一份 `Dockerfile`）  
3. 加极简网页（Streamlit/Gradio 任选）只做输入输出  
4. 读一个小开源项目的入口文件，画请求链路  

然后进入转岗路径，并把时间投给 [需求发现](../02-交付方法论/需求发现与问题拆解.md) 与 [Decomposition](../04-面试通关/Decomposition拆解面.md)。
