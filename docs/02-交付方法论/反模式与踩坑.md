# 反模式与踩坑

收集 FDE / 企业 AI 交付中的高频失败模式。建议打印「症状 → 根因 → 纠正」表，挂在项目周报旁。

---

## 1. 问题定义类

| 反模式 | 症状 | 纠正 |
|--------|------|------|
| 方案先行 | 一上来选模型/框架 | 先写问题陈述与指标 |
| 万能机器人 | 开放域什么都答 | 收窄任务与知识边界 |
| 指标漂移 | 每周重新定义成功 | 冻结试点指标 |
| 只听管理层 | 一线不用 | 强制一线访谈与旁听 |
| 忽视非目标 | 范围无限 | 书面非目标 |

---

## 2. 技术与 AI 类

| 反模式 | 症状 | 纠正 |
|--------|------|------|
| Demo 驱动开发 | 只优化演示路径 | Eval 集含困难例与安全例 |
| 无检索的「知识库」 | 幻觉当事实 | RAG + 强制引用 + 拒答 |
| Agent 无限工具 | 越权、不可控 | 最小权限、HITL、允许列表 |
| 忽略成本 | 账单爆炸 | 预算、缓存、模型分级 |
| 微调崇拜 | 未试 prompt/RAG 就训 | 走决策树 |
| 日志裸奔 | PII 进第三方 | 脱敏、保留策略、私有部署评估 |
| 单次提示拼真相 | 复杂流程靠玄学 | 工作流拆分 + 校验器 |

详见 [03-AI落地](../03-AI落地/企业AI落地全景.md)。

## 5. 案例分析（合成）

### 案例 A：全自动客服三周翻车

- **经过**：管理层看了竞品 Demo，要求三周全自动。团队上线后出现错误退款建议。
- **根因**：无门禁、无 HITL、无 eval、范围=全量。
- **纠正**：回退到坐席助手；建立黄金集；错误升级人工；重新谈对外口径。

### 案例 B：知识库「准确率 90%」无法复现

- **经过**：汇报准确率来自 10 个精选问题。
- **根因**：无固定测试集；训练/测试污染。
- **纠正**：冻结 100 条分层抽样集；分类型报表；展示失败案例。

### 案例 C：权限用超级账号

- **经过**：Pilot 很快，生产卡在安全审计。
- **根因**：文档级 ACL 未设计。
- **纠正**：检索层注入用户身份过滤；补审计；延期但可过审。

## 7. 「只是临时的」与过早通用化

> 补充自现场演讲与 OpenAI FDE 访谈公开表述（链接见文末）。

### 每个黑客方案都会进生产

脚本能解燃眉之急，但不能代替产品判断。交付前自问：

1. 6 个月后凌晨两点会不会因它被叫起来？  
2. 这是为整个产品做对，还是只讨好这一家？  
3. 我离开后交给谁？出事谁负责？  

**最危险的一句话：「这只是临时的。」** 若它真解决了问题，它就会留下——按会跑 18 个月来交付。解决方案架构师可以负责「客户当下成功」；FDE 还要对**能否变成杠杆**负责。

### 过早通用化

先拿 ChatGPT 式「通用能力」去找企业问题，常变成高概念、无清晰痛点的部署，零到一做不出来。相反：**超级深入一个具体问题**，可通用的东西几乎总会冒出来。格言对照：先做不规模化的事（Paul Graham 语境），再谈平台。

### 把 FDE 只当市场推广延伸

早期公司若只当「多派几个人陪客户」，没有产品回流，会变成高价外包。见 [什么是 FDE §8](../01-角色认知/什么是FDE.md)、[解决方案产品化](../05-能力补强/解决方案产品化.md)。
